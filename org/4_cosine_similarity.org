* What we want to do: recommend movies

Our feature space is two-dimensional. Our features are:
1) action
2) comedy

We encode what the user is looking for as a *query* vector -- how much
action and how much comedy they want. We encode every movie in our
small catalog the same way. *Cosine similarity* then measures the angle
between the query vector and each movie's vector: the smaller the
angle (the closer the cosine value is to 1), the closer that movie's
genre mix is to what was asked for. We rank the catalog by that angle
and recommend the closest match(es) first.

* Two features, three movies, one query

Genres as a 2D vector: =[action, comedy]=. A movie that's pure action
is =[1, 0]=; pure comedy is =[0, 1]=; a movie that's both is =[1, 1]=.

#+begin_src python
  import numpy as np

  movies = {
      "Explosive Comedy": np.array([1, 1]),
      "Pure Action":      np.array([1, 0]),
      "Pure Comedy":      np.array([0, 1]),
  }
  query = np.array([1, 0])  # "I want an action movie"
  print("Query:", query)
#+end_src

#+RESULTS:
: Query: [1 0]

The =query= gets compared against each of the three movie vectors to
check how close it is to each of them.

* Put a number on the angle

The cosine similarity of two vectors measures the angle between them
and not their length. For q = query vector, and m = movie vector:

$$ \cos(\theta) = \frac{q \cdot m}{\|q\| \, \|m\|} $$

#+begin_src python
  def cosine_similarity(q, m):
      return (q @ m) / (np.linalg.norm(q) * np.linalg.norm(m))

  for title, vec in movies.items():
      sim = cosine_similarity(query, vec)
      angle_deg = np.degrees(np.arccos(np.clip(sim, -1, 1)))
      print(f"{title:<18} similarity = {sim:.3f}   angle = {angle_deg:.1f} deg")
#+end_src

#+RESULTS:
: Explosive Comedy   similarity = 0.707   angle = 45.0 deg
: Pure Action        similarity = 1.000   angle = 0.0 deg
: Pure Comedy        similarity = 0.000   angle = 90.0 deg

~@~ is NumPy's matrix multiplication operator. For 1D vectors, it
reduces to the dot product (~np.dot(q,m)~). [fn:1]

identical to it -- not a very convincing demo of *recommending*
anything. A mixed query makes the ranking more interesting: someone who

* Questions and Answers

- =movies= here only holds three placeholder titles at clean angles.
  What would you actually need to change to turn this into a real
  movie recommender?
  #+begin_quote
  Two things: the catalog and the vectors. =movies= would need many real
  titles instead of three, and each one's genre vector would need to
  come from real, often continuous data -- how much of each genre a
  movie actually is, e.g. =[0.8, 0.2]= for "mostly action, a little
  comedy" -- rather than a hand-picked 0/1 flag. The rest of the
  pipeline stays exactly the same: encode the query the same way,
  compute =cosine_similarity(query, vec)= for every movie in the
  catalog, and return the movies with the highest similarity (smallest
  angle) as the recommendations.
  #+end_quote

- Pure Comedy is perpendicular to the query -- similarity 0.0. What
  would it mean for two movies to have *negative* similarity here, and
  could that happen with these particular features (all 0 or 1)?
  #+begin_quote
  With 0/1 flags, no -- the dot product =q . m= is a sum of
  non-negative terms, so it can't go below 0. The floor is 0, reached
  when two movies share no genre at all -- exactly the =Pure Comedy=
  case here.

  You could manufacture negative values by assigning a new genre to
  another quadrant -- e.g. "documentary" at =[-1, 1]= -- and the
  arithmetic goes through fine, since cosine similarity doesn't care
  what label you attach to a coordinate. But that overloads the axis:
  the same coordinate now means "amount of action" for one movie and
  "documentary flag" for another, so a vector like =[-0.5, 0.9]= has no
  principled reading anymore. It also buys nothing, since the first
  quadrant alone already holds infinitely many directions for genre
  mixtures. Mathematically legal, semantically broken -- don't do it.
  #+end_quote

- Next week's assignment does the exact same computation, just with
  four features instead of two, and can't be drawn as an arrow picture
  anymore. What do you think stays the same, and what do you lose by
  going from 2D to 4D?
  #+begin_quote
  The formula, the math, and the interpretation stay identical --
  cosine similarity is defined the same way in any number of
  dimensions, and "closer to 1 means more similar direction" still
  holds exactly. What's lost is the ability to *see* it: a 2D angle can
  be checked by eye on paper, but nobody can visualize a 4D angle
  directly -- you have to trust the arithmetic instead. This is the
  general situation in ML: most real feature spaces have far more than
  2 or 3 dimensions, so geometric intuition has to be taken on faith
  even though the math keeps working exactly the same way.
  #+end_quote

* Footnotes

[fn:1] =np.clip(sim, -1, 1)= clamps =sim= to the range [-1, 1]: values
below -1 are pushed up to -1, values above 1 are pushed down to 1,
anything already in range is untouched. It's a safety guard for
=np.arccos=, which is only defined on [-1, 1] and errors (or returns
=NaN=) outside it. Cosine similarity is mathematically always in
[-1, 1], but floating-point rounding in the division can overshoot
that range by a tiny amount (e.g. =1.0000000002= for two identical
vectors) -- clipping guarantees =arccos= always gets a legal input,
without changing the result at the printed precision.
