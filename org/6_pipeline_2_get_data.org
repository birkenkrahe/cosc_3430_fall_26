* [Slides 11–12] What do you notice about this distribution?

#+begin_quote
The top of the distribution is capped at $500,001: many districts
pile up at exactly that value (they show as a cluster of outlier
points above the whisker). You can also see this in the
histograms. Capped values are a strong pattern and you don't want the
model to learn that.
#+end_quote

- What is capping/clipping/winsorizing?
  #+begin_quote
  This is not *truncating* (removing the values) but clipping the values
  to a chosen threshold - so e.g. a house value of $1,000,000 still
  appears in the data but its value is recorded as $500,001 (the cap).
  #+end_quote
- Why is this done?
  #+begin_quote
  Most likely to protect survey respondent privacy/anonymity for very
  high-value properties, since these outliers can otherwise easily be
  identified.
  #+end_quote

* [Slides 14–15] What do you see? Share all your observations.

#+begin_quote
1. =median_house_value= and =housing_median_age= appear *capped* at the
   top (values above the cap are recorded as the cap value: 500,001
   and 52).
2. =median_income= is not in USD: it is in tens of thousands of
   dollars (3 means about $30,000), and it is *clipped* at 0.5 (about
   $5,000) and 15 (about $150,000).
3. =total_rooms=, =total_bedrooms=, =population=, =households= are
   strongly *right-skewed* (=median_income= and =median_house_value=
   moderately): a few very large values pull the ~mean~ above the
   ~median~.
4. The features are on wildly different *scales*. Scaling matters
   before training.
5. =latitude= and =longitude= are bi-modal (two spikes): the two big
   metro areas, the San Francisco Bay Area (about 37.8°N, 122.3°W)
   and Los Angeles (about 34°N, 118°W) - compare the California map.
6. =median_income= is the most important predictor of the house price
   (according to domain experts): that's why we will use it for
   *stratified sampling* - cutting the data into strata (groups) - when
   we create the test set.
#+end_quote

* [Slides 16–17] Follow-up: linear regression features

Which features would you feed a linear regression model, and which
would you transform first? And why?

#+begin_quote
1. Transform (log transformation is standard): =total_rooms=,
   =total_bedrooms=, =population=, =households= - heavily right-skewed.
2. Use, with care: =median_income= (mildly skewed, clipped at both
   ends) and =housing_median_age= (capped at 52).
3. Not linear in price: =latitude=, =longitude= - two metro peaks; better
   used as engineered features (e.g. clusters or distance to the coast).
4. Problematic no matter what: =median_house_value= because of the
   capping, which disrupts the target variable (prices above $500,001
   will not be predicted). Géron's options: collect proper labels for
   the capped districts, or remove them from training and test sets.

*Why?* Linear regression assumes a linear relationship between each
feature and the target. Skewed features compress variation at the
high end - the model has a harder time detecting the
relationship. Log transform spreads the values more evenly.
#+end_quote

- The needs for transformation are addressed later when we talk about
  preparing the data for training.

- *Loading*: =pd.read_csv()= reads a CSV straight from a URL into a
  DataFrame.

  values, memory), ~describe()~ (summary statistics).
- *Missing data*: =total_bedrooms= had 207 missing values out of
  20,640 - visible only by comparing the non-null count to the row
  total.
- *The one categorical column*: =ocean_proximity= - inspect its
  distinct values with ~value_counts()~.
- *Spread and skew*: a large std relative to the mean, and mean >
  median, both signal a right-skewed distribution - visible in a
  boxplot and in histograms.
- *Capping*: =median_house_value= is capped at $500,001, likely to
  protect the privacy of owners of very expensive properties.
- *Next*: create a test set, before exploring the data any further.

* Glossary

| Term                  | Definition                                           |
|-----------------------+------------------------------------------------------|
| bimodal               | a distribution with two peaks, e.g.                  |
|                       | latitude/longitude (Bay Area, LA).                   |
| boxplot               | shows the IQR as a box, the median as a line inside  |
|                       | it, and outliers beyond the whiskers.                |
| capping               | also clipping or winsorizing - replacing values      |
|                       | above (or below) a threshold with that threshold,    |
|                       | instead of removing them.                            |
| DataFrame             | pandas' two-dimensional labeled table; each column   |
|                       | can hold a different dtype.                          |
| describe()            | prints summary statistics (count, mean, std, min,    |
|                       | quartiles, max) per numeric column.                  |
| head()                | prints the first rows of a DataFrame (default 5).    |
| histogram             | a bar chart of value counts over equal-width bins of |
|                       | one numeric feature.                                 |
| info()                | prints row/column counts, dtypes, non-null counts    |
|                       | and memory usage.                                    |
| IQR                   | Interquartile Range - the 75th percentile minus the  |
|                       | 25th; the width of the box in a boxplot.             |
| memory usage          | how much RAM a DataFrame occupies; info() reports it |
|                       | in MB.                                               |
| non-null              | not missing; a non-null count below the row total    |
|                       | means some values are NaN.                           |
| object (dtype)        | pandas' generic type for anything that isn't a       |
|                       | number, usually text read from a file.               |
| right-skewed          | a distribution with a long tail toward high values,  |
|                       | pulling the mean above the median.                   |
| value_counts()        | counts how many rows hold each distinct value of a   |
|                       | column; use on categorical data.                     |
