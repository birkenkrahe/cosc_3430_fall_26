* 5. Fit and predict ~model1~ (k = 1)

- To build =model1=, we only need to call =knn= (our classifier alias) and
  specify =k=, the number of nearest neighbors to be taken into account.
- To fit the model, we call ~knn.fit()~ on =model1=. The classifier has
  now memorized the geometric properties of our dataset.
- To make a prediction, we run ~knn.predict()~ on our new, unseen data
  in =x_new=.

  #+begin_src python :results output :exports both :session *Python* :python python3
    model1 = knn(n_neighbors=1)
    model1.fit(X, y)

    pred1 = model1.predict(x_new)
    print(pred1)
  #+end_src

  #+RESULTS:
  : [1]

- Why does this print as =[1]=?
  #+begin_quote
  Because ~model.predict()~ always returns a 1D array, not a scalar,
  even when predicting a single point. =x_new= has shape (1,2) so the
  prediction is returned as array([1]) which prints as [1].

  To return just the number, select the first index:
  #+end_quote

  #+begin_src python :results output :exports both :session *Python* :python python3 
    print(pred1[0])
  #+end_src

  #+RESULTS:
  : 1

* 6. Fit and predict ~model3~ (k = 3)

#+begin_src python :results output :exports both :session *Python* :python python3
  model3 = knn(n_neighbors=3)
  model3.fit(X, y)

  pred3 = model3.predict(x_new)
  print(pred3)
#+end_src

#+RESULTS:
: [1]

Notice that if you were to change k to 6 (the maximum value for this
dataset) then you would get a 'loan denied' (0) prediction because
you'd have a 3:3 tie. ~scikit-learn~ breaks that tie deterministically
using the first index with the maximum count (~np.bincount + argmax~),
and since 0 comes before 1, it wins the tie.

* NEXT 7. Find the nearest neighbors by hand

~knn.predict()~ hides the actual work. Here is what it does for our new
customer (~x_new~ = =[4, 5]=) in four steps: measure the distance to every
training point, sort, take the =k= closest, and let them vote.

1) *Differences.* Subtract =x_new= from every row of =X=. NumPy
   "broadcasts" the single row of shape (1,2) across all six rows of
   shape (6,2):
   #+begin_src python :results output :exports both :session *Python* :python python3
     print(X - x_new)
   #+end_src

   #+RESULTS:
   : [[-2 -2]
   :  [-2  0]
   :  [-1 -1]
   :  [ 0 -1]
   :  [ 1  1]
   :  [ 2  0]]

   Each row is (income difference, credit score difference) between
   one training customer and the new customer.

2) *Squared distances.* Square each difference and add up the two
   features of each row. ~axis=1~ means "sum across the columns", so
   you get one number per customer instead of one number in total:
   #+begin_src python :results output :exports both :session *Python* :python python3
     print(((X - x_new)**2).sum(axis=1))
   #+end_src

   #+RESULTS:
   : [8 4 2 1 2 4]

3) *Euclidean distances.* Take the square root (Pythagoras:
   $d = \sqrt{\Delta_{income}^2 + \Delta_{score}^2}$):
   #+begin_src python :results output :exports both :session *Python* :python python3
     d = np.sqrt(((X - x_new)**2).sum(axis=1))
     print(d.round(2))
   #+end_src

   #+RESULTS:
   : [2.83 2.   1.41 1.   1.41 2.  ]

   Customer 3 (=[4,4]=) is the closest at distance 1.0, customers 2
   (=[3,4]=) and 4 (=[5,6]=) follow at 1.41.

4) *Sort and vote.* ~np.argsort(d)~ does not return the distances
   sorted, but the *row numbers* in the order of increasing distance.
   The first =k= of them are the nearest neighbors; their labels
   =y[idx]= are the votes:
   #+begin_src python :results output :exports both :session *Python* :python python3
     print(np.argsort(d))         # all rows, nearest first
     idx = np.argsort(d)[:3]      # k = 3 nearest neighbors
     print(idx)
     print(y[idx])                # their labels = the votes
     print(np.bincount(y[idx]).argmax())  # majority vote
   #+end_src

   #+RESULTS:
   : [3 2 4 1 5 0]
   : [3 2 4]
   : [1 0 1]
   : 1

   Two of the three neighbors voted "approved", so the prediction is
   =1= - the same as ~model3.predict(x_new)~. For ~k=1~, only row 3
   votes (=y[3] = 1=), which explains the ~model1~ result, too.

Check: scikit-learn can return the neighbors it found itself. ~kneighbors~
gives the distances and the row numbers:

#+begin_src python :results output :exports both :session *Python* :python python3
  dist, ind = model3.kneighbors(x_new)
  print(dist.round(2))
  print(ind)
#+end_src

#+RESULTS:
: [[1.   1.41 1.41]]
: [[3 2 4]]

These are our three distances and our three row numbers.

* 8. Compare the predictions

#+begin_quote
Do the predictions differ? Why or why not?
#+end_quote

#+begin_quote
In this example, both ~k=1~ and ~k=3~ predict approval. The new
customer is located near points labeled 1, so both the closest single
neighbor and the majority of the three nearest neighbors vote for
approval.
#+end_quote

The two models agree on ~x_new~. Do they also agree on the six
customers we already know? Predict the labels of the training data
with each model and compare them with the true labels ~y~:

#+begin_src python :results output :exports both :session *Python* :python python3
  print("true: ", y)
  print("k = 1:", model1.predict(X))
  print("k = 3:", model3.predict(X))
#+end_src

#+RESULTS:
: true:  [0 0 0 1 1 1]
: k = 1: [0 0 0 1 1 1]
: k = 3: [0 0 0 0 1 1]

~k=1~ gets all six right. ~k=3~ gets customer 4 (=[4,4]=, approved)
wrong: its three nearest neighbors are itself (approved) and two denied
customers (=[3,4]= and =[2,5]=), so the vote is 1:2 for "denied".

To turn this into a single number, count the correct predictions. The
fraction of correct predictions is the *accuracy*. Comparing arrays with
~==~ gives ~True~ or ~False~ per customer, and ~.mean()~ of a boolean
array is the fraction of ~True~ values:

#+begin_src python :results output :exports both :session *Python* :python python3
  print(model3.predict(X) == y)            # True where the model is right
  print((model3.predict(X) == y).mean())   # fraction correct = accuracy
#+end_src

#+RESULTS:
: [ True  True  True False  True  True]
: 0.8333333333333334

The model has a method that does exactly this: ~model.score(X, y)~
predicts the labels of ~X~, compares them with the true labels ~y~ and
returns the accuracy:

#+begin_src python :results output :exports both :session *Python* :python python3
  print(f"k = 1: accuracy = {model1.score(X, y):.2f}")
  print(f"k = 3: accuracy = {model3.score(X, y):.2f}")
#+end_src

#+RESULTS:
: k = 1: accuracy = 1.00
: k = 3: accuracy = 0.83

So 5 of 6 correct (0.83) for ~k=3~ and 6 of 6 (1.00) for ~k=1~. ~score~
also works on new data with known labels. Suppose we learn later that
the new customer ~x_new~ was in fact approved (label 1):

#+begin_src python :results output :exports both :session *Python* :python python3
  print(model1.score(x_new, [1]))
  print(model3.score(x_new, [1]))
#+end_src

#+RESULTS:
: 1.0
: 1.0

- Is ~k=1~ the better model because its accuracy is 1.00?
  #+begin_quote
  No. This accuracy was measured on the *training data*, and ~k=1~
  cannot fail there: every training point is its own nearest neighbor
  (distance 0), so it always votes for its own label. Training accuracy
  rewards memorizing the data. What counts is how the model does on
  customers it has *not* seen - that is what the practice will explore
  with 80 applications, and what a test set measures.
  #+end_quote

* 9. Visualize decision regions

To understand how the model generalizes beyond the training points, we
can visualize the decision regions — the areas of the 2D feature space
that the model would classify as approved or denied for any
hypothetical customer, not just the six we trained on.

The idea is to create a fine grid of points covering the entire
income/credit-score plane, predict the class for each grid point, and
color the plane accordingly. Where the color changes is the decision
boundary — the line (or curve) separating the two regions.

We do this in three steps:
1) Build a dense 2D grid with ~np.meshgrid~
2) Run ~model.predict()~ on every grid point
3) Plot the colored regions with ~plt.contourf~, then overlay the
   training points and new customer

#+begin_src python :file ../img/loan2d_regions.png :results file graphics output :exports both :session *Python* :python python3
  plt.clf()

  model = model1

  xx, yy = np.meshgrid(
      np.linspace(1, 7, 200),
      np.linspace(2, 7, 200)
  )

  grid = np.c_[xx.ravel(), yy.ravel()]
  Z = model.predict(grid).reshape(xx.shape)

  plt.contourf(xx, yy, Z, alpha=0.3)
  plt.scatter(X[y==0, 0], X[y==0, 1], label="denied (0)")
  plt.scatter(X[y==1, 0], X[y==1, 1], label="approved (1)")
  plt.scatter(x_new[:,0], x_new[:,1], marker='x', s=100, label="new customer")

  plt.xlabel("Income ($10,000s)")
  plt.ylabel("Credit score (scaled)")
  plt.title("Decision regions for kNN")
  plt.legend()
  plt.savefig("../img/loan2d_regions.png")
#+end_src

#+RESULTS:
[[file:../img/loan2d_regions.png]]

*Code explanation:*

- ~plt.clf()~: Clear the current figure to start with a fresh plot.
- ~model = model1~: Select which trained kNN model to visualize (here: k = 1).
- ~np.meshgrid(...)~: Create a grid of evenly spaced points covering the 2D feature space.
- ~xx, yy~: Matrices representing all x- and y-coordinates in the grid.
- ~xx.ravel(), yy.ravel()~: Flatten the grid into 1D arrays.
- ~np.c_[...]~: Combine flattened x and y into a list of coordinate pairs — shape ~(num_points, 2)~.
- ~model.predict(grid)~: Predict class (0 or 1) for every point in the grid.
- ~reshape(xx.shape)~: Convert predictions back into grid shape for plotting.
- ~plt.contourf(xx, yy, Z, alpha=0.3)~: Draw filled regions showing predicted class across the plane.
