#+begin_src python :results output :exports both :session *Python* :python python3
  import pandas as pd
  import numpy as np
  import matplotlib.pyplot as plt
  from sklearn.model_selection import train_test_split

  housing_full = pd.read_csv("https://tinyurl.com/housing-csv")

  housing_full["income_cat"] = pd.cut(
      housing_full["median_income"],
      bins=[0, 1.5, 3.0, 4.5, 6.0, np.inf],
      labels=[1, 2, 3, 4, 5])

  strat_train_set, strat_test_set = train_test_split(
      housing_full, test_size=0.2,
      stratify=housing_full["income_cat"],
      random_state=42)

  for subset in (strat_train_set, strat_test_set):
      subset.drop("income_cat", axis=1, inplace=True)

  housing = strat_train_set.copy()
  housing.info()
#+end_src

* IN PROGRESS [Slides 8-11] Exploring correlation coefficients (Pearson, custom)

** [Slide 8] Pearson's coefficient, via ~corr()~

The ~pandas~ method ~corr()~ computes a correlation coefficient
between every pair of numerical attributes - by default the standard
(Pearson's) coefficient. It measures whether two features grow and
fall together: covariance normalized by the product of the standard
deviations.

For two features a and b with n values each and means ā and b̄,
Pearson's correlation coefficient is:

#+begin_example
       Σ (a - ā)(b - b̄)
r = ─────────────────────────
    √( Σ(a - ā)² · Σ(b - b̄)² )
#+end_example

- The numerator is the (unnormalized) covariance: a pair adds a
  positive term when a and b are both above or both below their
  means, and a negative term when one is above and the other below.
- The denominator normalizes by the spread of each feature, so r
  always lies between -1 and 1 and does not depend on units or scale.
- r = 1: perfect positive linear relationship; r = -1: perfect
  negative linear relationship; r = 0: no linear relationship.

** [Slide 10] A toy correlation, by hand

Where does -0.851 come from? Plug the data into the formula. Both
means are 0.25 (each column adds up to 1.0 over four rows):

| row | dogs | cats | a = dogs - ā | b = cats - b̄ |     a·b |     a² |     b² |
|-----+------+------+--------------+--------------+---------+--------+--------|
|   0 |  0.2 |  0.3 |        -0.05 |        +0.05 | -0.0025 | 0.0025 | 0.0025 |
|   1 |  0.0 |  0.6 |        -0.25 |        +0.35 | -0.0875 | 0.0625 | 0.1225 |
|   2 |  0.6 |  0.0 |        +0.35 |        -0.25 | -0.0875 | 0.1225 | 0.0625 |
|   3 |  0.2 |  0.1 |        -0.05 |        -0.15 | +0.0075 | 0.0025 | 0.0225 |
|-----+------+------+--------------+--------------+---------+--------+--------|
|   Σ |      |      |              |              |   -0.17 |   0.19 |   0.21 |

#+begin_example
r = -0.17 / √(0.19 · 0.21) = -0.17 / 0.19975 = -0.851
#+end_example

*What do you learn from this?*

#+begin_quote
- r = -0.85: =dogs= and =cats= move strongly in opposite directions -
  where one is high, the other is low.
- Rows 1 and 2 are mirror images, and they supply almost the whole
  numerator (-0.175 of -0.17).
- The matrix is *symmetric* (the transposed matrix is the same as the
  matrix), and the diagonal is 1.0: every feature correlates
  perfectly with itself.
#+end_quote

r is one number for the pair of whole columns - the vectors =dogs=
and =cats= with four entries each - not one number per row. Look at
the formula again: it is the *cosine similarity* from lecture 4,
applied to the vectors a and b after subtracting their means:

#+begin_example
         a · b
r = ───────────── = cos θ     a = dogs - ā,  b = cats - b̄
     ‖a‖ · ‖b‖
#+end_example

  a = df["dogs"] - df["dogs"].mean()   # center: subtract the mean

So r = -0.85 means: the two centered vectors point in almost opposite

** NEXT [Slide 11] A custom method: histogram intersection

- ~corr()~ can measure other things than linear co-movement: its ~method~
  parameter also accepts your own function, which takes two columns
  and returns one number. The docstring's own example,
  =histogram_intersection=, adds up the smaller of the two values in
  each row - how much the two histograms overlap:

  #+begin_example
  min(0.2, 0.3) = 0.2
  min(0.0, 0.6) = 0.0
  min(0.6, 0.0) = 0.0
  min(0.2, 0.1) = 0.1
  sum           = 0.3
  #+end_example

- Python code:
  #+begin_src python :results output :exports both :session *Python* :python python3
    def histogram_intersection(a,b):
        v=np.minimum(a,b).sum().round(decimals=1)
        return v

    print(df.corr(method=histogram_intersection))
  #+end_src

  #+RESULTS:
  :       dogs  cats
  : dogs   1.0   0.3
  : cats   0.3   1.0

- How the code works:
  + =histogram_intersection= takes two columns =a= and =b= - pandas
    passes them in as numpy arrays, one value per row.
  + ~np.minimum(a,b)~ compares the arrays row by row and keeps the
    smaller value of each pair: =[0.2, 0.0, 0.0, 0.1]=. (Not ~min()~,
    which returns one number for a whole array.)
  + ~.sum()~ adds them up: 0.3. ~.round(decimals=1)~ is only cosmetic:
    without it you see the floating-point artifact 0.30000000000000004.
  + The function returns one number for the pair of columns.
  + ~df.corr(method=...)~ normally takes a name (~"pearson"~ is the
    default, also ~"kendall"~ and ~"spearman"~), but it accepts any
    function of two columns that returns one number. ~corr()~ calls it
    for every pair of columns and arranges the results as a matrix.
  + Note that the function is passed without parentheses:
    =method=histogram_intersection= hands ~corr()~ the function itself,
    and ~corr()~ calls it. With =histogram_intersection()= Python would
    try to call it right away, without arguments, and fail.

- *Can you interpret this result?*
  #+begin_quote
  - 0.3: the two histograms share 30% of their mass. Rows 1 and 2 add
    nothing, because one of the two values is 0.
  - The overlap is a sum of non-negative minimums, so it can never be
    negative - unlike Pearson's r.
  - The matrix is again symmetric. The diagonal is always 1.0: pandas
    sets it to 1.0 for any custom method without calling the function.
    (Here the function would give 1.0 anyway, because each column adds
    up to 1.0.)
  #+end_quote

- Same data, two very different numbers - because the two methods
  answer different questions:
  + Pearson (-0.85): do the two columns grow and fall together?
  + Histogram intersection (0.3): how much do the two distributions
    overlap?

- *For machine learning:* Pearson asks whether one variable /predicts/
  another (choosing model inputs); overlap asks whether two datasets
  look alike (train vs. test sampling, data drift, class separation).

* [Slide 22] Summary

- *Scope*: this session works on =strat_train_set= (copied as
  =housing=) only - =strat_test_set= stays sealed (no data snooping).
- *Geographic plot*: ~housing.plot(kind="scatter", x="longitude",
  y="latitude")~ maps districts; ~alpha~ fixes overplotting by making
  points transparent; ~s=~ (size) and ~c=~ (color) add two more
  variables to the same 2D plot.
- *Correlation*: ~corr()~ computes Pearson's coefficient by default
  (and accepts a custom method). It ranges from -1 to 1, is symmetric,
  and the diagonal is always 1.0.
- *Same data, two questions*: on the dogs/cats toy data, Pearson
  gives -0.85 (the columns grow and fall in opposite directions),
  histogram intersection gives 0.3 (the two histograms overlap by
  30%).
- *Close to zero*: means no *linear* correlation - not necessarily no
  relationship at all.
- *median_income* is the feature most correlated with
  =median_house_value= (~0.69) - the same feature used for stratified
  sampling in part 3.
- *scatter_matrix()* plots every pair of a chosen attribute list
  against each other; the diagonal can show a histogram or a KDE
  (density) plot instead.
- *Zooming in* on =median_income= vs =median_house_value= shows the
  capping at $500,000 and straight-line artifacts - likely data
  collection quirks, not real patterns.
- *Attribute combinations*: =bedrooms_ratio= (r = -0.26) correlates
  more strongly with house value than the raw totals it is built from.
- *Next*: prepare the data for learning (cleaning, encoding, scaling).

* Glossary

** Plotting

| Term                      | Definition                                       |
|---------------------------+--------------------------------------------------|
| alpha (blending)          | Point transparency, 0 = invisible to 1 = opaque  |
| colormap (~cmap~)         | Maps a numeric column to color, e.g. ~"jet"~     |
| KDE                       | Kernel Density Estimate: a smoothed histogram    |
| ~scatter_matrix()~        | pandas: plots every pair of chosen attributes    |

** Correlation

| Term                      | Definition                                       |
|---------------------------+--------------------------------------------------|
| correlation coefficient   | Number from -1 to 1 measuring linear association |
| covariance                | Average product of deviations from the means     |
| Pearson's coefficient     | Covariance divided by both standard deviations   |
| ~corr()~                  | pandas: r for every pair of numeric columns      |
| custom method (~method=~) | Own function: two columns in, one number out     |
| histogram intersection    | Overlap of two histograms: sum of row minimums   |
| symmetric matrix          | A matrix equal to its own transpose              |
| attribute combination     | New feature built from existing ones, e.g. ratio |
